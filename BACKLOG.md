**D. Сроки retention — по каждой категории ПДн.**
- **🔴 RKN-AUDIT-01 — политики хранения (retention) нет ни для одной категории ПДн** *(filed 2026-07-31)*. Единственная временная отсечка во всём коде — `NOTIFICATION_RETENTION_DAYS = 30` (`delete-account.ts:8`), и применяется только при удалении аккаунта, а не фоном. Периодических джобов очистки нет (греп `deleteMany` по `worker.ts` + `lib/queue/*` — пусто; `media.cleanup` чистит orphan-загрузки, это не retention). Записи, чаты, отзывы, логи, аудит, `RefreshSession` хранятся бессрочно. **→ промпт `RKN-FIX-04-retention-policy.md` (medium)**, сроки определяет юрист. **⚠️ Ограничение, которое retention обязан учесть (из RKN-FIX-02/-03-A):** строки `RefreshSession` **нельзя просто удалять по сроку**. Логаут и удаление аккаунта их **отзывают** (`revokedAt`), а не стирают, намеренно: ПДн в них нет, но их наличие — единственный маркер «этот профиль когда-то был аккаунтом», на котором держится anti-forgery-предикат `isGuestClassProfile`. Вычистив старые сессии, мы сделаем удалённый/старый аккаунт снова похожим на «гостевой» профиль, и анонимная гостевая бронь начнёт писать `UserConsent` от его имени. Retention для этой таблицы должен либо сохранять маркер иным способом, либо не трогать её вовсе. **⚠️ Второй вход (добавлено 2026-08-03 из RKN-FIX-10): `PdAccessLog` обязан получить конечный срок хранения.** Таблица заводилась ради scoping инцидента и содержит **IP актора**; при удалении аккаунта `actorUserId` обнуляется (`SetNull`), но осиротевшая строка с IP остаётся — то есть без retention «право на забвение» протекает через журнал, который его же и защищает. Ориентир для юриста: срок должен покрывать реалистичное окно обнаружения инцидента (утечки находят месяцами, не днями), но не быть бессрочным. Чистка — обычным периодическим джобом, ничего специального.
→ Код-потребитель: **RKN-FIX-04**. ⚠️ Два инженерных ограничения, которые юрист должен учесть: (1) `RefreshSession` нельзя чистить по сроку — строки держат маркер «профиль был аккаунтом», на котором стоит anti-forgery `isGuestClassProfile`; (2) `PdAccessLog` содержит IP актора и **обязан** получить конечный срок, иначе право на забвение протекает через журнал, который его же защищает.

### 🔑 Вход по телефону — если он нужен публичной стадии

- **🔴 AUTH-GATE-01 tails — SMS-провайдер, затем `PHONE_AUTH_ENABLED=true` в prod** *(filed 2026-07-31; код готов, это deploy-ops)*. Вход по телефону теперь за env-килсвитчем `PHONE_AUTH_ENABLED` (tri-state: unset → ON в dev, **OFF в prod**). Пока OFF: таб «Телефон» отсутствует на `/login`, `POST /api/auth/otp/{request,verify}` → 503 `SYSTEM_FEATURE_DISABLED` (до генерации/записи/логирования кода), CTA «Вход» скрываются, только если не включён **ни один** другой метод (email-OTP / VK / Yandex); `/login` тогда отдаёт graceful-состояние «Вход скоро будет доступен». Форма всюду одна: сервер отрендерил `style={{opacity:"0", transform:"translateY(…)"}}` — начальное состояние анимации, — а клиент под `useReducedMotion()` хочет `style={{}}`, и React пишет «This won't be patched up».
