## А. Данные, деньги, время

1. **«Итоги недели» — сумма в 100 раз больше.** `src/lib/master/weekly-stats-job.ts:73-80` складывает
   `priceSnapshot` в копейках, а `src/lib/ui/text.ts:1096` печатает число как рубли (`toLocaleString` + «₽»):
   4 500 ₽ приходят как «450 000 ₽». Исправить: в тексте — через общий форматтер копеек (`UI_FMT.priceLabel` /
   `moneyRUBFromKopeks`), тип аргумента — `Kopeks`. Тест на текст уведомления.

2. **Движок снова открывает старую неделю после конца графика.** Периоды графика грузятся уже отфильтрованными
   по диапазону (`src/lib/schedule/engine-context.ts:206-207`), а развилка «есть график → только график, иначе
   неделя» (`engine-context.ts:572-576`) смотрит на отфильтрованный список. Когда настроенный график кончился,
   список пуст, и профиль с перенесённой неделей получает окошки по старой неделе, хотя каталог его уже скрыл
   (нарушено решение «расписание действует ровно до настроенной даты»). Исправить: признак «у профиля вообще
   есть график» брать без фильтра по датам (есть агрегат по `SchedulePattern` на строке ~301), неделю читать
   только при его отсутствии. Заодно `copyProviderScheduleTx` пишет неделю новому профилю в студии — писать
   график. Это этап 0 спеки 17; делается здесь, **до первого деплоя графиков**. Тест: график кончился вчера →
   сегодня выходной, окошек нет.

3. **Автосозданный город получает пояс Москвы.** Город из геокодера вне справочника из 8 (Самара, Хабаровск…)
   рождается с `Europe/Moscow`: окошки мастера из Самары съезжают на час, студии из Хабаровска — на 7 часов, а
   поправить пояс сам провайдер не может; правка пояса города в админке до провайдеров не доходит, и форма
   правки не показывает текущий пояс, если его нет в списке. Исправить: пояс нового города — по координатам /
   ответу геокодера (способ выбрать при правке, см. шаг 5 спеки 27); правка пояса города в админке
   распространяется на провайдеров этого города с поясом по городу; форма показывает текущее значение. Убрать
   полный адрес из лога автосоздания. Проверка: город вне справочника → верный пояс, окошки в поясе салона.

4. **Даты на сервере по часам контейнера (rule 17).** `admin-body-templates.ts:131` («Доступ сохранится до …»)
   и `studio-today-banner.tsx:20` (у студии в Екатеринбурге с 00:00 до 05:00 — вчерашний день). Перевести на
   пояс получателя / салона с меткой (`formatBillingDeadlineLabel`, `toLocalDateKey`). Сторож
   `billing/deadline-label.test.ts` ловит только `dateRU` — расширить на `toLocaleDateString` без `timeZone` в
   серверных модулях.

5. **Журнал чтений персональных данных по CRM не пишется.** `master.clients.list` и `studio.clients.list`
   пишут только API-роуты `GET /api/master/clients` и `/api/studio/clients`, которые интерфейс не вызывает;
   настоящие страницы «Клиенты» (`getMasterClientsView`, `loadStudioClientsData`) след не пишут. Контекст §10
   утверждает обратное. Исправить: `recordPdAccess` в оба сервиса страниц; поправить §10. Тест: открытие
   списка клиентов пишет одну строку `PdAccessLog`.

6. **`OtpCode` с почтой не удаляется** ни при удалении аккаунта (там чистка только по телефону), ни фоном.
   Исправить: удалять и по почте аккаунта; добавить фоновую чистку просроченных кодов (например, в воркере раз
   в сутки). Уведомления удалённого аккаунта (удаляются старые, остаются свежие) — решение в спеке 26, вопрос 7.

## Б. Интерфейс и тексты

7. **«Опасные» кнопки не красные в светлой теме** (минимум 6 мест, например «Удалить кабинет» —
   `src/features/master/components/account/account/danger-zone-card.tsx:91`): `variant="ghost"` несёт
   `text-text-main`, и он перебивает `text-rose-700` (плоский `cn`). Исправить так же, как «Удалить работу»:
   `variant="wrapper"` и токены `text-danger-text` / `hover:bg-danger-surface` / `border-danger-border`. Найти
   все места: `ghost`/`secondary` с `text-rose-*`/`text-red-*`. Системно класс закрывает спека 12.

8. **Профиль клиента: заглушка «Удаление аккаунта скоро появится»** набрана прямо в коде
   (`client-profile-page.tsx`, `DangerZoneCard onDelete`), хотя удаление работает в `/cabinet/settings`.
   Исправить: кнопка ведёт в настройки к удалению (или открывает тот же диалог); строка — из `UI_TEXT`.

9. **Строки мимо `UI_TEXT`:** русский текст прямо в `studio-booking.ts`; загрузчики кабинета клиента бросают
   `"load_failed"` — проверить, доходит ли он до экрана, и заменить на `UI_TEXT`.

10. **Ошибки секций публичных страниц на проде не записываются:** оба `block-error.ts` выходят сразу по
    `isProduction` и пишут `console.error`. Перевести на `logError` + `reportError` (трекер), в проде тоже.

11. **Неопубликованный профиль ссылается на OG-картинку, которая всегда 404.** Не отдавать ссылку на превью,
    пока профиль не опубликован (или отдавать общую картинку).

12. **Лишние запросы на публичных страницах:** блок отзывов опрашивает `/api/reviews/can-leave` по одной записи
    клиента за раз (свести к одному запросу), для гостя зовёт `/api/me/bookings` и всегда получает 401 (не
    звать без сессии); страница студии дважды запрашивает одни и те же фото.

13. **Замена фото: старое удаляется до загрузки нового.** При сбое загрузки работа (у студии — сейчас, у мастера
    — после спеки 01) остаётся с битой картинкой. Исправить порядок в `POST /api/media` с `replaceAssetId`:
    сначала сохранить новое, затем удалить старое.

14. **Цена в запросе к ИИ в копейках, подписана как рубли:** `suggest-description/route.ts:72` → `prompts.ts:95`.
    Из интерфейса недостижимо, но правка — одна строка.

15. **Мёртвый код:** компонент `share-profile-section` нигде не используется. Удалить. (`GET /api/favorites` без
    вызывающих — решение в спеке 31, вопрос 2 про неиспользуемые API.)
