# 12 · `tailwind-merge` внутри `cn`

**Источник:** `CN-MERGE-PROPOSAL` (BACKLOG) · **Тип:** нужно решение → рефакторинг · **Объём:** M
**Зависит от:** — . Делать **до** 22 (сырые кнопки) и 23 (`dark:`-оверрайды): их миграции опираются на то, что `className` вызывающего побеждает вариант. Пересекается с 25 (типографика): часть «живых» конфликтов — это `text-[10px]`.

## Что не так

`cn` — плоский join (`src/lib/cn.ts:1-3`). Когда примитив и вызывающий задают одно свойство, побеждает не порядок аргументов, а порядок правил в собранном CSS, и он свой у каждого семейства утилит. Класс дефектов повторяется: FIX-ROUND-02 (вариант `inverted`), UI-26 (`wrapper` глушил заливку, 3 поверхности), CN-CONFLICT-CLASS (93 живые коллизии, закрыты точечно `defaultUnlessOverridden`), PWA-FIX-12 (ширина `Input`, группы не было в инвентаре), 29.09 — «Удалить работу» в окне изменения работы портфолио была не красной: `variant="ghost"` несёт `text-text-main` (`src/components/ui/button.tsx:32`), `.text-text-main` в бандле ниже `.text-rose-700` (строки 6342 и 6300) и выигрывает. На рабочей копии этот сайт уже переведён на `variant="wrapper"` + `text-danger-text`, но класс жив.

**Пересчёт на 2026-09-29.** Бандл собран `tailwindcss/lib/cli.js` (10 373 строки), конфликт определён самим `tailwind-merge@2.6.1` с расширением под токены проекта (ниже), «живой» = сегодня побеждает дефолт примитива, `tailwind-merge` перевернёт в пользу вызывающего; «латентный» = вызывающий уже побеждает, картинка не изменится. **Прежний инвентарь занижал счёт** (BACKLOG: «перечислял группы вручную»): в нём не было цвета текста, высоты, размера шрифта и ширины. Здесь группы определяет сама библиотека.

**Вес.** `tailwind-merge@2.6.1`, собрано esbuild с минификацией: 19,9 КБ / **6,7 КБ gzip**, с расширением под токены — 20,4 / 6,9 КБ gzip. Для масштаба: утечка рантайма Prisma в клиент (PERF-11) была 21 КБ gzip. Время — разбор строки с LRU-кэшем на 500 записей; на 372 вызова `cn` заметной цены нет.

**Версия.** Tailwind проекта — 3.4 (`package.json:101`). `tailwind-merge` 3.x поддерживает только Tailwind 4 — нужна ветка **2.x** (`^2.6`), иначе разбор классов будет неверным.

**Токены проекта, которые библиотеку надо научить понимать** (`tailwind.config.js`), проверено на установленном пакете:
- тени `soft`/`card`/`hover`/`glow`/`brand` — без расширения `shadow-card` считается ЦВЕТОМ тени: `cn("shadow-card", "shadow-primary/20")` выбрасывает `shadow-card`, а `cn("shadow-lg", "shadow-card")` оставляет обе (в CSS обе — `box-shadow`);
- фоны-картинки `brand-gradient`/`brand-gradient-soft` — без расширения считаются цветом фона: `cn("bg-brand-gradient", "bg-bg-card")` молча выбрасывает градиент;
- цвета (`bg-bg-card`, `text-text-main`, `border-border-subtle`, `*-success-surface` и т.д.), `font-display`, экран `xs` — работают без расширения;
- авторские классы `lux-card`, `lux-input`, `glass-panel`, `scrollbar-hide` — библиотека их не трогает.
Использований кастомных теней и градиентов в `src/` — 192.

**Поведение библиотеки, о котором надо знать:** поздний размер шрифта выбрасывает ранний `leading-*` (в Tailwind 3 `text-sm` задаёт и высоту строки). Так перевернётся `src/components/ui/stat-tile.tsx:133` (`leading-tight … text-[10px]`) — правило для кода: `leading-*` ставить после `text-*`.

## Что сделать (если решение «да»)

1. **Инвентарь в репозиторий.** `scripts/inventory-cn-conflicts.mjs` (инструмент, не гейт): собирает бандл, обходит JSX примитивов из `src/components/ui/` и вызовы `cn(`, печатает живые и латентные конфликты с номерами строк бандла. Прошлый скрипт CN-CONFLICT-CLASS жил только в отчёте и потерялся — второй раз не терять. Прогнать, сохранить список живых сайтов в отчёт.
2. **Разбор живых сайтов до переключения** (по областям, со снимками до/после в обеих темах): на каждом решить — намерение автора верно (оставить класс, после переключения он заработает) или нет (удалить класс, чтобы картинка не изменилась). Ориентиры: «опасные» кнопки — сразу на `variant="wrapper"` + `text-danger-text`/`hover:bg-danger-surface` (как уже сделано в `edit-item-modal.tsx`); `Input px-3` — оставить; `Badge text-[10px]` — удалить (спека 25: ниже 12px не опускаемся); `leading-*` перед `text-*` — переставить.
3. **Переключение.** `npm i tailwind-merge@^2.6`; `src/lib/cn.ts`:
   ```ts
   import { extendTailwindMerge } from "tailwind-merge";
   const twMerge = extendTailwindMerge({ extend: { classGroups: {
     shadow: [{ shadow: ["soft", "card", "hover", "glow", "brand"] }],
     "bg-image": [{ bg: ["brand-gradient", "brand-gradient-soft"] }],
   } } });
   export function cn(...classes: Array<string | undefined | null | false>) {
     return twMerge(classes.filter(Boolean).join(" "));
   }
   ```
   Сигнатура не меняется — 214 импортов не трогаются.
4. **Удалить обходной механизм.** `src/lib/ui/class-groups.ts` (`defaultUnlessOverridden`) и его вызовы в шести примитивах (`Skeleton`, `badge`, `card`, `empty-state`, `input`, `stat-tile`) → обычный `cn(дефолт, className)`. `src/lib/ui/class-groups.test.ts` с реестром `HARD_DEFAULTS_ALLOWED` удалить: «жёсткий дефолт» теперь уступает вызывающему по порядку аргументов, а реестр фиксировал 0 коллизий по форме компонентов.
5. **Сторож** `src/lib/cn.test.ts` (поведенческий):
   - по одному случаю на семейство, где порядок в бандле обратный порядку аргументов (радиус `rounded-xl`→`rounded-full`, отступ `px-4`→`px-3`, цвет текста `text-text-main`→`text-rose-700`, высота `h-11`→`h-10`, фон `bg-transparent`→`bg-bg-card`, ширина `w-full`→`w-[6.5rem]`): побеждает последний аргумент;
   - токены из `tailwind.config.js` читаются из самого конфига (`theme.extend.boxShadow`, `backgroundImage`, а также `fontSize`/`borderRadius`/`spacing`, если появятся) — для каждого ключа проверяется, что `cn` его не выбрасывает рядом с цветом той же утилиты. Новый токен без записи в `extendTailwindMerge` краснеет;
   - `@probe`: убрать `"card"` из расширения → красный на `shadow-card shadow-primary/20`; заменить `cn` обратно на join → красные все случаи семейств.
6. **Документы кода:** комментарии «`cn` — плоский join» в `button.tsx` (`:38-40`, `:51-73`, `:88-91`) и `eslint.config.mjs:76-79` (категория 3 исключений: «хром `ModalSurface` нельзя нейтрализовать без tailwind-merge» — теперь можно; отметить для `OVERLAY-FULLBLEED-PORTAL-PRIMITIVE`). Скилл `ui-ux-pro-max`: разделы «Выбор варианта `Button`» и «Дефолт примитива не должен зависеть от порядка в бандле» переписать — побеждает последний аргумент `cn`; `leading-*` после `text-*`; новые тени/градиенты — только вместе с записью в `cn.ts`.

**Если решение «нет»:** закрыть 95 живых сайтов точечно и расширить `class-groups.ts` группами `text-color`, `height`, `font-size`, `shadow`, а `Button` перевести на `defaultUnlessOverridden` по группам каждого варианта. Это дорастить свою копию `tailwind-merge` на регулярках, и каждая новая утилита остаётся ручной работой.

## Решения владельца

**Подключать ли `tailwind-merge` в `cn`?**
- **Да (рекомендую).** +6,9 КБ gzip клиенту и одна зависимость. Класс «написал класс — не применился» исчезает целиком: он возвращался пять раз, каждый — живой дефект на экране. Цена разовая — разбор ~95 живых сайтов со снимками (шаг 2); латентные ~170 картинку не меняют.
- **Нет.** Без зависимости; но 95 живых сайтов всё равно чинить руками, а механизм `defaultUnlessOverridden` придётся расширять на каждое новое семейство.

## Риски

- Главный — одномоментная смена ~95 мест, вокруг части из них дизайн мог быть нарисован как есть. Поэтому шаг 2 обязателен до переключения, а не после («компилируется — значит ок» здесь не работает).
- Статический анализ не видит `className`/`variant`, собранные в переменных (у `Button` — 279 из 552 вызовов); после переключения — пройти глазами ключевые экраны кабинетов, а не только список.
- Новые токены теней/градиентов без записи в `cn.ts` молча ломают сочетания — ловит сторож из шага 5, только если токен объявлен в `tailwind.config.js`, а не в `globals.css` напрямую.
- Обновление `tailwind-merge` до 3.x запрещено, пока проект на Tailwind 3 (зафиксировать в комментарии `cn.ts` и в §2 контекста).
