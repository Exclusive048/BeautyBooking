# 27 · Фильтр страны для автосоздания городов

**Источник:** `GEO-CITY-COUNTRY-FILTER` (BACKLOG, из RF-ONLY-SCOPE-01, флаг 3) · **Тип:** доработка + нужно решение (да/нет) · **Объём:** S
**Зависит от:** — (парная спека 28 закрывает ручной канал — выбор пояса)

## Что не так

- `detectCityFromAddress` (`src/lib/cities/detect-city.ts:44-144`) пускает любую locality, которую знает Яндекс, — контракт записан прямо в коде (`:34-36`). Незнакомый город создаётся на лету (`:92-117`, `autoCreated: true`, `isActive: true`). Решение RF-ONLY-SCOPE-01 («только Россия», контекст §8) этот канал не закрыл: мастер сохраняет «Алматы, ул. Достык, 89» → появляется `City` «Алматы» → провайдер попадает в каталог с казахстанским городом.
- Геокодер для фильтра уже всё отдаёт: `geocodeWithLocality` (`src/lib/cities/yandex-locality.ts:92-151`) читает `GeocoderMetaData.Address.Components`, где есть компонент `kind: "country"`, а у `Address` — поле `country_code` («RU»). Сейчас тип ответа (`:28-47`) их не описывает и `extractLocality` (`:79-85`) берёт только `locality`/`province`. Лишний запрос для фильтра не нужен.
- **Запись BACKLOG неточна:** город создаётся не с `Asia/Almaty`, а с `DEFAULT_TIMEZONE = "Europe/Moscow"` (`detect-city.ts:28,102`). Алматинский мастер получает не только чужую страну, но и московское время.
- Вызывающих двое, и отказ они обрабатывают по-разному. Мастер (`src/lib/master/profile.service.ts:434-453`): при `ok: false` адрес сохраняется, `cityId` → null, мастер молча выпадает из каталога. Студия (`src/lib/studios/studio.ts:176-181`): при `ok: false` город и пояс не трогаются — новый адрес пишется рядом со СТАРЫМ городом. Просто вернуть из детектора новый отказ поэтому мало: у студии адрес и город разъедутся.
- ⚠️ Не было в BACKLOG — **адрес в логах:** `logInfo("city.auto_created", { …, triggerAddress: address })` (`detect-city.ts:108-112`) пишет адрес целиком. У мастера, работающего из дома, это домашний адрес, то есть ПДн, а маскировки нет.
- ⚠️ Не было в BACKLOG — **пояс автосозданного города внутри РФ тоже неверен.** В справочнике 8 городов (`prisma/seeds/reference/catalog-reference.ts:34-41`). Любой другой — Самара (+4), Омск (+6), Хабаровск (+10) — создаётся с Москвой. Правка пояса города админом (`src/app/api/admin/cities/[id]/route.ts:79`) на провайдеров не распространяется: `Provider.timezone` выводится только при сохранении адреса. У студии пояс в кабинете только для чтения (`features/studio-cabinet/components/studio-profile-form.tsx:288-293`), и она поправить его не может вовсе. Это отдельный дефект, но канал тот же.

## Что сделать

1. `yandex-locality.ts`: добавить в тип `Address.country_code?: string` и вернуть `countryCode: string | null` в `YandexLocalityResult`. Если `country_code` нет, брать запасной вариант — компонент `kind: "country"` («Россия» → `RU`).
2. `detect-city.ts`: новый отказ `reason: "foreign_country"`. Он проверяется до поиска и создания города, **и для уже существующего города тоже**, иначе заведённая раньше «Алматы» продолжит принимать адреса. Поведение при `countryCode === null` — вопрос 2.
3. Вызывающие отказывают в сохранении адреса, а не молча выводят из каталога: 422 с кодом `ADDRESS_OUTSIDE_RUSSIA` (новый код в `ERROR_CODES`, `src/lib/api/errors.ts`) и строкой из `UI_TEXT` («Сейчас принимаем адреса только в России. Проверьте адрес.»). Адрес не пишется ни у мастера, ни у студии. Прочие отказы (`geocoder_failed`, `no_locality`) ведут себя как раньше.
4. Лог `city.auto_created`: убрать `triggerAddress`, оставить `citySlug`/`cityName` — город ПДн не является.
5. **Связанный дефект пояса — по ответу на вопрос 3.** Рекомендуемый объём: (а) при автосоздании определять пояс по субъекту РФ — компонент `kind: "province"` уже есть в ответе — через статическую таблицу «субъект → IANA» в `src/lib/cities/region-timezones.ts`; для многопоясных субъектов (Якутия, Сахалинская область) и незнакомого субъекта — Москва + сигнал админу; (б) правка пояса города в админке переносит его на провайдеров этого города, у которых пояс совпадал со старым поясом города, то есть не был выставлен вручную.

## Решения владельца

1. **Включаем фильтр страны?** Да / нет. **Рекомендация: да.** Это единственный автоматический путь не-РФ данных в прод. Цена — предикат, код ошибки, строка `UI_TEXT` и тест.
2. **Если в ответе геокодера страны нет:** **А** — пустить, записать в лог (рекомендация: у адресов, по которым Яндекс нашёл locality, страна на практике есть всегда, а ложный отказ стоит мастеру регистрации); **Б** — отказать. Последствие А: канал закрыт не на 100%, и лог покажет, насколько.
3. **Пояс автосозданного города (шаг 5)** — делаем в этой же спеке? **Рекомендация: да, (а)+(б).** Иначе у мастера из Самары окошки съезжают на час, а у студии из Хабаровска — на 7 часов, и студия это никак не поправит. Если нет — завести отдельным пунктом `CITY-AUTOCREATE-TZ`.
4. **Уже созданные не-РФ города на проде:** перед выкладкой прогнать инвентарь (запрос ниже). Найденные — выключить (`isActive = false`) руками в `/admin/cities`, а мастерам написать. Код их не трогает. Да?

```sql
SELECT c.slug, c.name, c.timezone, c."autoCreated", count(p.id) AS providers
FROM "City" c LEFT JOIN "Provider" p ON p."cityId" = c.id
GROUP BY c.id ORDER BY c."autoCreated" DESC, providers DESC;
```

## Готово, когда
- Адрес за пределами РФ не сохраняется ни у мастера, ни у студии, человек видит понятную причину; новый `City` не создаётся; существующий не-РФ город новые адреса не принимает.
- В логах автосоздания нет адреса.
- (Если принят вопрос 3) автосозданный город в РФ получает пояс своего субъекта; правка пояса города доходит до его провайдеров.
