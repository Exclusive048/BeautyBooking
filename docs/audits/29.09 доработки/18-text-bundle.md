## Что сделать
Приём — **пространство имён вместо объекта**: `text.ts` становится барелем именованных экспортов по доменам, потребители пишут `import * as UI_TEXT from "@/lib/ui/text"`. Webpack 5 отслеживает статический доступ `UI_TEXT.<домен>.…` у namespace-импорта и берёт только нужные модули; сами обращения (`UI_TEXT.common.cancel`) не меняются ни в одном файле — меняется одна строка импорта. Почему не «импорт домена напрямую» (шаг 2 плана BLOCKED): дифф в тысячи строк и два способа писать одно и то же; инвариант #13 при namespace сохраняется буквально.

**Этап 1 — раскладка без изменения поведения** (выкатывается сам, бандл не меняется).
1. Разовым скриптом (не в репозиторий) разрезать литерал: 61 файл `src/lib/ui/text/<домен-kebab>.ts`, в каждом `export const <домен> = {…} as const;` — тело ветки байт в байт, с комментариями; `import { pluralize } from "@/lib/utils/pluralize"` — только там, где он вызывается.
2. `src/lib/ui/text.ts` → 61 строка `export { common } from "./text/common";` + временно `export const UI_TEXT = { common, … } as const;` (обратная совместимость до этапа 2).
3. `scripts/check-ui-text.mjs` (UI-19): читать все `src/lib/ui/text/*.ts`; контроль машинерии на фикстуре — строка с «...» обязана ловиться (GUARD-INTEGRITY п. 2: не-вакуумность не по размеру находок).

**Этап 2 — namespace-импорт** (здесь появляется выигрыш; один механический коммит).
1. Кодмод по 689 файлам: `import { UI_TEXT } from "@/lib/ui/text"` → `import * as UI_TEXT from "@/lib/ui/text"`. Удалить временный объект этапа 1 — `typecheck` найдёт всё пропущенное.
2. `next.config.ts` → `webpack`: правило `{ test: /src[\\/]lib[\\/]ui[\\/]text(\.ts|[\\/])/, sideEffects: false }` — барель и домены чистые, правило гарантирует, что неиспользуемые реэкспорты отбрасываются независимо от эвристики webpack. Замер до/после этапа подтверждает.

**Этап 3 — вынести ключи шелла из крупных доменов.** `clientCabinet.switcher.*` → `nav.cabinetSwitcher.*`; `publicProfile.hero.novice` → `common`; `models.list` → `footer`; `notificationsCenter.openAction` → `notifications`; на публичном профиле `master.reviews` → `publicProfile`. Итоговый список брать обходом графа (сторож этапа 4), а не этим перечнем. Ожидание по исходнику: шелл ~30 kB, `/` ~43, `/catalog` ~48, `/u/[username]` ~74 (вместо 505).

**Этап 4 — сторожа.**
1. `src/lib/ui/text-client-graph.test.ts` — обход графа как в `src/lib/prisma-enums.test.ts` (импорты разбирает компилятор, value-рёбра от каждого `"use client"`, стоп на `"use server"`):
   - (а) в клиентском графе нет формы, отключающей отслеживание доступа у namespace: `UI_TEXT` как значение без `.`, `UI_TEXT[`, `= UI_TEXT`, передача `UI_TEXT` аргументом;
   - (б) **замороженный инвентарь** доменов, достижимых из клиентского графа `src/app/layout.tsx`, — падение на росте с именем модуля и цепочкой импортов.
   `@probe` (правдоподобные формы): вернуть `UI_TEXT.clientCabinet.switcher.label` в `auth-user-menu.tsx` → (б) красный с цепочкой `layout → topbar → auth-user-menu`; в `fmt.ts` написать `const T = UI_TEXT; T.common.cancel` → (а). В шапке назвать слепую форму: реэкспорт namespace через промежуточный модуль (`export * as T from "@/lib/ui/text"`) и доступ уже через него — такой модуль добавить в запрещённые формы, если появится.
2. **Поведенческий, по сборке:** `scripts/check-client-text-bundle.mjs`, шаг после `next build` в `.github/workflows/build-images.yml` (единственный CI-гейт, который собирает). По `page_client-reference-manifest.js` маршрутов `/`, `/catalog`, `/u/[username]`: в чанках нет маркеров доменов `adminPanel`, `studioCabinet`, `cabinetMaster` (маркер — первая строковая константа домена, выводится из файла, не пишется руками); first-load JS маршрута (gzip) ≤ замер этапа 3 + 5 %. `@probe`: `UI_TEXT.adminPanel.aria.sidebar` в `auth-user-menu.tsx` → маркер найден в чанках `/`.
