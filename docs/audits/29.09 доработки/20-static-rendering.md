# 20 · Статический рендер: `cookies()`/`headers()` из корневого layout

**Источник:** `PERF-01` (`docs/audits/AUDIT-FRESH-04-performance.md` § PERF-01; разбор — `AUDIT-CAMPAIGN-BLOCKED.md` § PERF-01) · **Тип:** нужно решение · **Объём:** L (вариант C — S)
**Зависит от:** — Вес бандла (18, 19) от режима рендера не зависит, их можно вести раньше.

## Что не так
Замер 2026-09-29 (код) и сборки 2026-09-23 (`.next/prerender-manifest.json`): пререндерены только `/_global-error`, `/favicon.ico`, `/robots.txt`, `/sitemap.xml`; **все 90 страниц динамические**. В `src/` 0 вхождений `revalidate`, `unstable_cache`, `"use cache"`, `revalidateTag`.

**От запроса шелл зависит в пяти местах, а не в двух** (аудит и BLOCKED видели nonce и cookie-уведомление):
1. `src/app/layout.tsx:75-77` — `generateViewport` читает `headers()` (User-Agent): iOS получает `maximumScale: 1` (`src/lib/pwa/viewport.ts`, PWA-ZOOM-01). В аудите не упомянуто.
2. `layout.tsx:177` — `getNonce()` → `headers()` (`src/lib/csp/nonce.ts:3-5`). Nonce нужен трём местам: `<meta property="csp-nonce">` (`:191`), инлайн-скрипт сброса SW (`:192`, текст `:37-68`), `ThemeProvider nonce` (`:200` → `components/theme-provider.tsx:11` — инлайн-скрипт `next-themes` против вспышки темы).
3. `layout.tsx:185-187` — `cookies()`: подавление cookie-уведомления на сервере (RKN-FIX-06).
4. `components/layout/topbar.tsx:140` — `getSessionUser()` (`lib/auth/session.ts:157` → `cookies()` + запрос к БД): шапка персональная — ярлыки кабинетов, меню, колокольчик; у вошедшего ещё до 5 запросов в `loadWorkspaceLinks` (`topbar.tsx:63`). В аудите не упомянуто.
5. `src/proxy.ts:558-610` ставит на каждый HTML-ответ (matcher `:622-626`) CSP `script-src 'self' 'nonce-…' 'strict-dynamic' https:` без `'unsafe-inline'`. Статическая страница nonce в разметке не несёт — в проде браузер заблокирует её инлайн-скрипты (RSC-данные `self.__next_f.push`, скрипт темы). Next прямо пишет: статика, ISR и PPR несовместимы с nonce-CSP (`node_modules/next/dist/docs/01-app/02-guides/content-security-policy.md:385-397`); экспериментальный SRI (`:456-540`) покрывает только внешние файлы. В dev CSP не ставится вовсе (`proxy.ts:599-610`) — дефект такого рода локально не воспроизводится.

Статике **не** мешают: город (`CityPromptOverlay`, `CitySelector` — клиентские), `resolveAuthMethods`, статистика футера (`footer/Footer.tsx:66`, Redis) — это данные, их переварит `revalidate`.

**Страницы** (транзитивный обход серверного графа от каждой `page.tsx` вне кабинетов и админки):
- **Без собственных динамических чтений — 16:** `/403`, `/about`, `/become-master`, `/blog`, `/book`, `/careers`, `/consent`, `/faq`, `/gift-cards`, `/help` (только `searchParams` вкладки, `help/page.tsx:30-31`), `/how-it-works`, `/how-to-book`, `/offline`, `/partners`, `/privacy`, `/terms` (`getLegalDraftMode` — данные, Redis 30 с).
- **Персональные по сути — статикой не станут ни при каком варианте:** `/` (`app/page.tsx` → `getSessionUser`), `/catalog` (`features/catalog/pages/catalog-page.tsx:3,11` — избранное), `/u/[username]` (`owner-view.ts`, `sections/hero-section.tsx`, `sections/reviews-section.tsx:41` `cookies()`, `searchParams`, nonce JSON-LD `u/[username]/page.tsx:241,388,407`), `/pricing`, `/models`, `/support`, `/login`, `/notifications`.

Итого приз статики — **16 текстовых страниц с малым трафиком**; горячие маршруты остаются динамическими. Цена запроса сегодня: на каждом просмотре шапка делает 2 запроса к БД за логотипом без кэша (`lib/media/queries.ts:20-45`, `:81-86`), у вошедшего плюс сессия и до 5 запросов ярлыков.

## Что сделать
Три варианта, выбор — владельцу (см. ниже). Рекомендация — **C сейчас**.

**(C) Не менять режим рендера, снять стоимость запроса** — решения не требует.
1. `getSiteLogoAsset` — кэш в Redis по образцу `getLegalDraftMode` (`lib/legal/config.ts:21-34`) + сброс при смене логотипа (`lib/media/service.ts:520`, `:753`). Тест: второй вызов не ходит в Prisma; смена логотипа сбрасывает.
2. Замер TTFB на прод-сборке до/после — `/terms`, `/`, `/u/anna-sokolova`, аноним и вошедший. Если шапка вошедшего даёт > 50 мс — отдельным шагом кэш `loadWorkspaceLinks` на пользователя (60 с, сброс при создании/удалении кабинета и смене аватара).

**(A) Шелл без зависимости от запроса + CSP в двух режимах.**
1. Viewport: статический `BASE_VIEWPORT`; поправка iOS — клиентский эффект (`components/pwa/ios-viewport-fix.tsx` дописывает `maximum-scale=1` в `<meta name="viewport">` после гидратации; автоприближение бывает только при фокусе поля, а поле до гидратации не интерактивно).
2. Cookie-уведомление решает клиент: SSR не рендерит его никому, клиент показывает, если куки `mr_cookie_notice` нет. Подтвердившему не мигает (цель RKN-FIX-06 сохранена), новому посетителю появляется после гидратации.
3. Персональная часть `Topbar` → клиентский островок (новый `/api/me/shell`, SWR); SSR рисует нейтральную заглушку правой части, а не «Войти», — иначе у вошедшего мигнёт гостевая шапка. **Видимое изменение на каждой странице.**
4. Nonce уходит из layout: два постоянных инлайн-скрипта (тема, сброс SW) → хэши `'sha256-…'` в CSP; на динамических страницах Next сам ставит nonce своим скриптам, разбирая заголовок (`content-security-policy.md:181-193`).
5. `proxy.ts`: для списка статических путей — CSP без nonce, `script-src 'self' 'unsafe-inline' https:` (RSC-данные инлайновые и разные у каждой страницы — хэшами не покрываются); обновление сессии на этих путях пропускать, как для `PUBLIC_REFERENCE_API_PATHS` (`proxy.ts:439`), иначе `Set-Cookie` уедет в кэш. Список путей — одна константа на proxy и сторожа.
6. 16 страниц: `export const revalidate = 300`; `/help` читает вкладку `useSearchParams` на клиенте.

**(B) Отдельный корневой layout для 16 страниц:** удалить `app/layout.tsx`, завести `app/(site)/layout.tsx` (всё как сейчас) и `app/(content)/layout.tsx` (пункты A.1–A.6 только для группы); API-роутам layout не нужен. Цена: переход между группами — полная перезагрузка (`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/layout.md:142-145`), перенос всех страниц в группы, дубль шелла, `global-not-found`.

## Решения владельца
1. **Вариант: A / B / C.** Рекомендация — **C**: без решения по безопасности, S, даёт TTFB на всех маршрутах. A/B — только при внешней причине (SEO юрдокументов, CDN перед стендом). Между ними B дешевле: понижение CSP и клиентская шапка ограничены 16 текстовыми страницами, A задевает шапку каждой страницы.
2. **Если A или B:** принять `script-src 'unsafe-inline'` на 16 статических путях. На них нет пользовательского ввода и отражения — инъекции некуда встать, но модель CSP становится двухрежимной (правка §10 контекста).
3. **Если A:** cookie-уведомление появляется после гидратации, а не в первом кадре — подтвердить, что для информационного уведомления правового слоя это допустимо.

## Готово, когда
- **C:** при тёплом кэше просмотр страницы не читает логотип из БД (счётчик Prisma в тесте); таблица TTFB p50/p95 до/после — в отчёте.
- **A/B:** в `prerender-manifest.json` — 16 путей (ISR); на них в прод-сборке 0 нарушений CSP в консоли, тема без вспышки, баннер по п. A.2; остальные маршруты — динамические с nonce, как сейчас.

## Проверка
- `npm run build` — таблица маршрутов и `routes` в `.next/prerender-manifest.json`.
- **A/B, юнит:** CSP по пути (статический / динамический); хэши инлайн-скриптов = sha256 их текста — сторож с `@probe`: поменять байт в `LOCAL_SW_RESET_SCRIPT` → красный с именем скрипта.
- **A/B, по сборке:** список статических путей сверяется с фактически пререндеренными из манифеста (вывод, а не сверка списка с самим собой; GUARD-INTEGRITY п. 2).
- **Живая:** прод-сборка `node .next/standalone/server.js` (при `output: standalone` `next start` не работает — контекст §9), в Playwright `serviceWorkers: "block"`; телефон (iOS-эмуляция: фокус в поле не приближает) и ПК; обе темы без вспышки; аноним и вошедший — шапка; консоль — CSP.
- **TTFB:** `for i in $(seq 50); do curl -o /dev/null -s -w "%{time_starttransfer}\n" http://127.0.0.1:3000/terms; done` → p50/p95; так же `/` и `/u/anna-sokolova`.

## Риски

- **(A/B) `Set-Cookie` обновления сессии в кэше** → чужая сессия у следующего посетителя (урок PERF-13, §11).
- **(A)** мигание шапки у вошедшего на всех страницах; **(B)** полная перезагрузка при переходе из футера на юрдокумент и обратно.
- `/offline` прекэширует SW (`next.config.ts:26`) — при статике проверить, что ревизия обновляется на деплой.
